# LEGALHUSTL Video Engine — безкоштовний хмарний відеорендерер

Автоматичний рендер коротких Reels та Stories для юридичної Instagram-сторінки. Відео створюються на GitHub-hosted runner за допомогою FFmpeg. Комп'ютер користувача не бере участі в роботі й може бути вимкнений.

## Формат відео

- Reels: 14 секунд (у межах обраних 10–15 секунд).
- Stories: 12 секунд.
- 1080 × 1920, 30 кадрів/с, MP4 (H.264 + AAC).
- Темно-синя / синя / золота айдентика LEGALHUSTL.
- Чотири змінні сцени з анімованою графікою, переходами та динамічними текстовими блоками українською.
- Музика створюється алгоритмічно під час рендеру; голосу немає, зовнішні музичні треки не використовуються.
- Без платних відеогенераторів, API генерації відео, стокових відео та локального комп'ютера.

**Це motion-design, а не генерація кінематографічних сцен нейромережею.** Такий варіант є стабільним і відтворюваним за нульової вартості відеогенерації. Відео не створює вигадані сцени судів, військових або подій; у ньому використовується контрольована графіка й текст із затвердженої чернетки.

## Схема роботи

1. Apps Script додає юридично схвалений Reels або Story до аркуша `Video Jobs`.
2. GitHub Actions запускається приблизно кожні 10 хвилин і звертається до захищеного Apps Script Web App.
3. Worker отримує завдання, рендерить MP4 на хмарному Ubuntu runner через FFmpeg.
4. MP4 повертається у Apps Script через токенізований вебміст.
5. Apps Script зберігає MP4 в `GOOGLE_DRIVE_FOLDER_ID/LEGALHUSTL Video Engine`, відкриває доступ за посиланням та додає `VIDEO|https://...` до відповідного рядка календаря або Stories.
6. Існуючий механізм публікації Instagram працює далі зі своїми юридичними й часовими перевірками.

## Одноразове налаштування

### 1. Оновити Apps Script

1. Зроби резервну копію таблиці та Apps Script.
2. Замінити основний `Instagram.gs` файлом `apps-script/Instagram.gs` із цього пакета.
3. `API secret.gs` залишити без змін. **Не завантажувати його до GitHub.**
4. Зберегти код і перезавантажити Google Таблицю.

### 2. Розгорнути захищений Apps Script Web App

1. У меню таблиці: `Instagram → Діагностика й ручні інструменти → Створити токен Cloud Video Bridge`.
2. Скопіювати токен із діалогу. Він записується в Script Properties, але ніколи не зберігається у вихідному коді.
3. В Apps Script натиснути `Deploy → New deployment → Web app`.
4. Встановити `Execute as: Me` та `Who has access: Anyone`, розгорнути та скопіювати URL, який закінчується на `/exec`.
5. У таблиці виконати `Зберегти URL Cloud Video Bridge` і вставити цей URL.
6. Виконати `Перевірити Cloud Video Bridge`. Має з'явитися повідомлення, що міст працює.

Вебміст доступний за URL, але всі дії вимагають довгий випадковий токен. Якщо адміністратор Google Workspace забороняє доступ `Anyone`, такий спосіб розгортання не працюватиме без іншого автентифікованого шлюзу.

### 3. Створити GitHub-репозиторій

1. Створити **публічний** репозиторій `legalhustl-video-engine`.
2. Завантажити в репозиторій вміст цього проєкту зі збереженням структури, особливо `.github/workflows/render.yml`.
3. Не завантажувати `API secret.gs`, токени, ключі або особисті дані.

Публічний репозиторій потрібен для безкоштовного використання стандартних GitHub-hosted runners. Код у репозиторії буде публічним; секрети зберігаються окремо в GitHub Secrets. Для приватних репозиторіїв GitHub Free має місячний ліміт включених хвилин, і регулярне опитування черги може його перевищити.

### 4. Додати два GitHub Actions secrets

У репозиторії відкрити `Settings → Secrets and variables → Actions → New repository secret` та створити:

| Назва | Значення |
|---|---|
| `APP_SCRIPT_BRIDGE_URL` | URL Apps Script Web App `/exec` |
| `VIDEO_BRIDGE_TOKEN` | Токен, створений через меню таблиці |

Потім відкрити `Actions → LEGALHUSTL Cloud Video Renderer → Run workflow` для першого тестового запуску. Надалі workflow перевірятиме чергу приблизно раз на 10 хвилин. Розклад GitHub є best-effort і може затримуватися; це не система real-time.

## Робота після встановлення

- Схвалені Reels і кадри Stories автоматично потрапляють у `Video Jobs`.
- Один запуск GitHub Actions обробляє до двох завдань.
- Готові MP4 зберігаються в Google Drive та прив'язуються до активного рядка.
- Reels повертаються до звичайного календарного механізму публікації.
- Story типу `REPLY` може йти штатним API-маршрутом після перевірок. Для `POLL`, `QUIZ`, `QUESTION`, `SLIDER` нативний стікер потрібно додати в Instagram вручну: Instagram Graph API не створює ці інтерактивні стікери.
- Комп'ютер може залишатися вимкненим після одноразового налаштування.

## Безпека та межі

- Personal Access Token GitHub не потрібен. Workflow використовує стандартний read-only `GITHUB_TOKEN`.
- Вебміст Apps Script приймає тільки запити з правильним `VIDEO_BRIDGE_TOKEN`.
- Розмір MP4 обмежений 9 МБ, щоб передача base64 не перевищувала безпечний розмір запиту Apps Script.
- Google Drive файл стає доступним усім, хто має посилання, оскільки Instagram має завантажити MP4. Не додавай до відеозавдань приватні або конфіденційні матеріали.
- Генерація відео безкоштовна за умови використання публічного репозиторію та стандартних runner-ів; залишаються наявні витрати Google/OpenAI/Meta інших компонентів Autoposting.
- Успішний рендер ще не означає юридичного схвалення або публікації. Контент має пройти чинні перевірки Autoposting.

## Опційні тести розробника

Ці команди потрібні лише для локальної розробки самого репозиторію; для щоденної роботи їх запускати на комп'ютері користувача не потрібно.

```bash
python -m pip install -r requirements.txt
python -m unittest discover -s tests -v
python renderer.py --job sample-job.json --output sample.mp4
```
