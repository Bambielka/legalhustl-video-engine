# SENTINEL LAW Motion Engine V4

Редакційний motion-design рендерер для Instagram Reels і Stories. V4 зберігає чинний контракт Cloud Video Bridge і додає автоматичний вибір структури відео за змістом матеріалу.

## Що змінилося у V4

- Дев'ять типів відео з окремими композиціями: новина/зміни, правове пояснення, інструкція, міф/правда, судова практика, чекліст, порівняння, питання/відповідь, юридичний ризик.
- Для кожного типу є дві альтернативні розкладки. Варіант визначається стабільно за ID контенту та номером сцени, щоб ролики не виглядали однаково.
- Обкладинки також отримують різні графічні мотиви відповідно до типу матеріалу.
- Класифікація працює за `topic`, `headline` і `script`. Додатково підтримується необов'язкове поле `video_type`, але поточна черга Google Sheets його не потребує.
- Парсер відсікає режисерські та монтажні примітки, зокрема заголовки на кшталт `ВІЗУАЛЬНІ ПРИМІТКИ:` і рядки-інструкції `ВИКОРИСТОВУВАТИ...`.
- Підписи `МІФ:` і `ПРАВДА:` зберігаються як змістові мітки. Інші дозволені поля сценарію (`ФАКТ`, `УМОВА`, `ЩО ВАЖЛИВО`, `ДІЯ` тощо) очищаються від міток, але їхній текст залишається.
- Повний текст матеріалу зберігається у нижньому текстовому блоці. Верхня інфографіка показує короткі фрагменти, а не дублює весь абзац.
- Використовується та сама стилістика SENTINEL LAW: світлий редакційний фон, чорна типографіка, фіолетові акценти, кінетичні переходи. Ведучий/обличчя та випадкові стокові люди не використовуються.

## Типи відео

| Внутрішній тип | Застосування | Приклади композиції |
|---|---|---|
| `news` | Нормативні зміни, офіційні рішення, нові програми | Новинний бюлетень, таймлайн |
| `explainer` | Пояснення механізмів і правових конструкцій | Карта понять, редакційні шари |
| `howto` | Практичні алгоритми та порядок дій | Вертикальні кроки, картки кроків |
| `myth_fact` | Спростування міфів | Розділений екран, поетапне розкриття |
| `case` | Судові справи та правові позиції | Таймлайн справи, досьє |
| `checklist` | Переліки документів, умов і перевірок | Сітка чекліста, вертикальний список |
| `comparison` | Порівняння процедур, станів «було/стало» | Дві колонки, баланс |
| `qa` | Відповіді на конкретні запитання | Велика картка питання, акцент на відповіді |
| `risk` | Помилки, строки, відповідальність і наслідки | Попередження, маршрут ризику |

Тип обирається за текстовими сигналами, тому класифікація є евристичною, а не юридичним аналізом. За відсутності чіткого сигналу застосовується `explainer`. Зміст і правові твердження не переписуються рендерером.

## Контракт та архітектура

Google Sheets → Apps Script → `Video Jobs` → GitHub Actions → `worker.py` → `renderer.py` → FFmpeg → Google Drive → Instagram.

`worker.py`, Apps Script, токен Cloud Video Bridge, URL мосту та GitHub Secrets не змінюються. Функція `build_video(job, output_path)` і поля черги залишаються сумісними з поточною системою. Новий стовпець у Google Sheets не потрібен.

## Формат і обмеження

- 720 × 1280, 30 fps, H.264 + AAC stereo.
- Reels — адаптивна тривалість відповідно до сценарію та темпу читання.
- Stories — окремий 12-секундний формат; нативні інтерактивні стікери Meta, як і раніше, потребують ручного додавання.
- Цільовий розмір MP4 — до 8.5 MB, із запасом до ліміту Cloud Video Bridge 9 MB.
- Музика — синтезований оригінальний стереотрек; голос ведучого не генерується.
- Якщо сценарій перевищує ліміт або відео виходить за розмірний бюджет, завдання завершується помилкою, а текст не обрізається мовчки.

## Локальна перевірка

```bash
python -m pip install -r requirements.txt
python -m unittest discover -s tests -v
python renderer.py --job sample-job-v4.json --output sample-v4.mp4
```

Потрібні `ffmpeg` і `ffprobe`, а також DejaVu Sans із підтримкою української мови.

## Редакційна безпека

- Генератор не є фактчекером і не підтверджує чинність норм. Контент проходить чинний процес юридичної перевірки та схвалення до постановки в чергу.
- Графічні підписи є структурними елементами дизайну. Генератор не додає до сценарію нових юридичних прав, обов'язків, строків, сум або номерів статей.
- Візуальні фрагменти скорочуються для композиції; повний аудиторний текст залишається в нижньому блоці.
- Неоднозначні теми можуть потрапити до типу `explainer`; перед публікацією відео потрібно переглядати.
