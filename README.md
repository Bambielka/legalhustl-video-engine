# SENTINEL LAW Motion Engine V4.1

Редакційний motion-design рендерер для Instagram Reels і Stories. V4.1 зберігає чинний контракт Cloud Video Bridge та додає стабільний вибір візуальної композиції за типом матеріалу.

## Що виправлено у V4.1

- Виправлена обробка коротких сценаріїв у форматах `howto` та `checklist`: кількість графічних блоків тепер відповідає фактичній кількості фрагментів; немає звернення до відсутніх елементів списку.
- Виправлено розпізнавання технічного заголовка `ВІЗУАЛЬНІ ПРИМІТКИ:` та інших режисерських інструкцій. Технічний текст не виводиться на екран; явні поля аудиторного тексту зберігаються.
- Порівняльний макет більше не вигадує другу сторону, коли сценарій її не містить.
- Варіант композиції обирається один раз на відео за `content_id` і лишається стабільним у межах ролика. Різні матеріали одного типу можуть отримувати різні варіанти.
- Для типу `qa` питання з заголовка передається в сцену окремо від відповіді; візуальна картка питання не підмінює його текстом відповіді.
- Виправлена перевірка MP4/FFprobe та закриття stderr-потоку FFmpeg.
- Додані тести рендерингу 18 варіантів композицій, коротких сценаріїв, обкладинок, фінальних кадрів, Stories і контрольного MP4.
- GitHub Actions запускає тести на `push` до `main` і на Pull Request. На звичайний `push` `worker.py` не запускається та не звертається до Video Bridge.

## Дев'ять типів відео

| Внутрішній тип | Призначення | Варіанти композиції |
|---|---|---|
| `news` | Новини та нормативні зміни | Новинний бюлетень, таймлайн |
| `explainer` | Юридичні пояснення | Карта понять, редакційні шари |
| `howto` | Покрокові інструкції | Вертикальні кроки, картки кроків |
| `myth_fact` | Міф / правда | Розділений екран, поетапне розкриття |
| `case` | Судові справи та правові позиції | Таймлайн, судове досьє |
| `checklist` | Переліки документів та умов | Сітка, вертикальний список |
| `comparison` | Порівняння та «було / стало» | Дві колонки, композиція з балансом |
| `qa` | Питання та відповіді | Картка питання, акцент на відповіді |
| `risk` | Помилки та юридичні ризики | Попередження, маршрут ризику |

Підтримується необов'язкове поле `video_type` у завданні. Воно не потребує нового стовпця в Google Sheets: якщо поля немає, тип визначається евристично за `topic`, `headline` і `script`. Евристика може помилитися; відео потрібно переглядати перед публікацією.

## Архітектура та сумісність

Google Sheets → Apps Script → `Video Jobs` → GitHub Actions → `worker.py` → `renderer.py` → FFmpeg → Google Drive → Instagram.

Публічний контракт `build_video(job, output_path)` не змінений. `worker.py`, Apps Script, URL Cloud Video Bridge, токен і GitHub Secrets залишаються сумісними. Новий стовпець у таблиці не потрібен.

## Вихідний формат

- 720 × 1280, 30 fps.
- H.264 video + AAC stereo audio.
- Reels — адаптивна тривалість за обсягом сценарію та часом читання.
- Stories — 12 секунд.
- Цільовий розмір MP4 — до 8.5 MB, із запасом до ліміту Cloud Video Bridge 9 MB.
- Музика — оригінальний синтезований стереотрек; голос ведучого не генерується.
- Не використовуються обличчя користувача чи випадкові стокові люди.

## Локальна перевірка

Потрібні Python 3.13, FFmpeg, FFprobe та DejaVu Sans. На Ubuntu:

```bash
sudo apt-get update
sudo apt-get install -y ffmpeg fonts-dejavu-core
python -m pip install -r requirements.txt
python -m py_compile renderer.py worker.py tests/test_renderer.py
python -m unittest discover -s tests -v
python renderer.py --job sample-job.json --output sample-v4.mp4
```

## GitHub Actions

- `push` до `main` і Pull Request запускають тільки тестовий job.
- `schedule` (кожні 10 хвилин) та `workflow_dispatch` запускають тести, а після їх успіху — окремий job рендерингу черги.
- На звичайний `push` секрети не використовуються і відеозавдання з Google Sheets не забираються.

## Редакційна безпека

- Рендерер не є юридичним фактчекером і не визначає чинність норм.
- Рендерер не додає нових прав, обов'язків, строків, сум або номерів статей.
- Графічні підписи є елементами дизайну; короткі фрагменти беруться з тексту сценарію.
- Повний аудиторний текст кожної сцени зберігається в нижньому caption-блоці. Технічні примітки видаляються до рендерингу.
- Матеріал потрібно переглядати перед публікацією.
